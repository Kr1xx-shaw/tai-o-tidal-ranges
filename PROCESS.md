# Process

## Tools
I first asked Codex to read and summarise the assignment requirements, then returned to the course repository to check them one by one. I chose the circular tide chart from the reference examples because it interested me, and asked AI to help explore available data, write most of the Python code, draft the documentation and check the results.
My workflow was to describe an idea through prompts, ask AI for a visual preview, and judge whether it matched what I had in mind before making further changes. Early concepts used AI image generation, while the final charts were drawn by Python using real data. I followed this process from a single flat layer to twelve overlapping months, then to a perspective view and an interactive version. Sometimes AI added useful details that I had not specified. For example, I requested vertical separation between the monthly layers, and it also added mouse rotation, point inspection on hover and month visibility controls.

The final tide chart uses Python and Matplotlib to draw from the saved Hong Kong Observatory data. The interactive version uses PySide6 Essentials to embed a Matplotlib 3D canvas in a native Qt window. Dependencies are declared in the script so uv can install the required plotting and window libraries automatically. The course’s circular tide example informed the angle-and-radius mapping. However, this project uses twelve months of Tai O data and calculates the difference between the highest and lowest of each day’s 24 hourly predictions, rather than reproducing the classroom’s hourly tide chart for Quarry Bay.
I mainly directed the visual choices: three separate months became overlapping outlines, then expanded to six months and finally a full year. I requested muted blue-green, pink and yellow colours, retained the orange maximum markers and added black minimum markers. After comparing the flat image with a 45-degree perspective, I chose the flat view for the main PNG. I later requested a separate interactive version with a vertical slider to spread the monthly layers, and reviewed a visual preview before implementation.
During verification, I compared the data with the official tide table and questioned why its values differed from those used by the program. This helped me understand that predictions at the times of high and low water are not necessarily the same as hourly samples, and that the displayed decimal precision also differs. Codex checked all 365 dates and 8,760 hourly values and compared the saved data with the official source, confirming that the fields and values matched.


## Kept
I kept a shared radial scale and a fixed 31-position angular scale because the same date within each month should appear in the same direction. This makes comparisons between months easier. I also kept light transparent fills and monthly maximum and minimum markers so that the outlines and key points remain identifiable when layers overlap.
In the interactive version, the slider changes only the vertical spacing between months; it does not change the dates or daily ranges. Hovering over a point shows its date, range, and the highest and lowest hourly predictions used to calculate that range. Month buttons allow individual layers to be inspected. I kept these controls because they help me move from looking at the overall shape to checking specific values.
The raw data remains unchanged, and the static and interactive versions use the same validation and radius calculations. Once uv has installed the declared dependencies, the desktop window can read the repository’s data offline. The README still embeds the static PNG so the result can be viewed directly.


## Rejected or Corrected
I rejected the dense annual daylight stripe chart because it looked too crowded. I also rejected the AI-generated daylight rings because the months looked almost identical, making it difficult to judge whether the shapes reflected real differences in the data.
I did not replace the flat PNG with a perspective view because perspective changes apparent distances and makes direct comparison of radii harder. Instead, the perspective view became a separate interactive companion, with a top-view control and exact values available on hover.
I also rejected the initial HTML delivery because opening it was inconvenient. I wanted the chart to open directly after entering uv run interactive.py in the VS Code terminal, so I requested a native window. Codex replaced the browser implementation and removed the HTML output.
During data checking, I clarified the meaning of the values and replaced the broad description “daily tidal range” with “the difference between the highest and lowest hourly tide predictions for each day.” Hourly sampling can miss a high or low occurring between samples, so this calculation should not be treated as identical to subtracting the values in the official high-and-low tide table.
Month-end joins are dashed and explicitly described as graphical closures, not additional measurements. The final scripts also validate dates and values and report errors when data cannot be parsed, rather than silently discarding rows.
